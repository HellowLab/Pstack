# Render a chart with available tools

Provide the Mermaid source even when image rendering is unavailable. The upstream rendering reference targets Pele SVG output, but this adaptation bundles no renderer and does not install Pele, npm packages, Java or TLC. Check the actual host/project renderer, output support and authorization first. If Pele was explicitly requested and is unavailable, disclose the gap; do not silently substitute another renderer. A manually drafted chart remains unverified after rendering.

Use authorized scratch output outside the project unless the user requested project artifacts. Keep source and rendered output paired. Render only with inspected, available tooling and record the actual version and command. On a rendering error, provide the Mermaid text and the actual error; never invent an image or claim inspection of an image you cannot open. Do not copy upstream resource-limit options into another renderer without checking its API and capacity.

Preserve the distinction between `breaks` (all represented states violate a named rule) and `mayBreak` (some do), groups, bug paths and repeating property states. Group colors must not conceal rule marks. Explain each named rule in the legend. A repeated-state border is evidence only when the actual checker report supports it. SVG styles and Mermaid class definitions may override one another; inspect the actual output instead of assuming a theme or palette applied. Check light/dark readability when supported, labels, arrow conditions and numbered paths. If rendering or visual inspection cannot run, state that limitation and provide the source.

Upstream's pinned Pele version, CSS and installation instructions remain source data. No native SVG rendering, tool installation, exhaustive model check or successful visual inspection is implied by this guidance.
