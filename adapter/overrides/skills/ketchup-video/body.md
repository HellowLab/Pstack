# Ketchup video

Follow `/ketchup` through the host's actual skill catalog for complete context, status verification and every waiting user decision. The window starts at the last user-authored message before this invocation, not before an earlier ketchup. Do not inspect unrelated chats or private storage.

Keep the underlying work read-only. Creating and rendering this recap in an authorized scratch location outside the repository is the only exception. Verify that video rendering, file access, frame inspection and embedding are actually supported. Do not install tooling, start the application, capture new screens, post externally or change project files just to make a recap. If rendering or inspection is unavailable or fails, say so in one line and give only the waiting calls, including their options, links, evidence and risks; do not pretend a storyboard is a rendered video.

## Story and slides

Use screenshots, recordings, diffs and data the work actually produced, not unsupported claims in the chat. Privately choose one takeaway sentence and one point per slide. Keep at most 10 slides and drop slides that add no information. Use one evolving picture, consistent color/shape meanings, and arrows or motion to identify changes. Slides are not bullet/status lists, tables or disconnected boxes.

Use minimal plain-language labels on the things they name. Do not repeat facts across slides or text. Show the outcome of each requested item as done, running, failed or not checked, including bugs found and fixed. Never mark work waiting on the user as done. For a visible change without a screenshot, say that on its slide and name the change. Never invent numbers or draw a screen you did not capture. Use only existing authorized evidence.

## Subtitles

Give each slide one short subtitle, about ten words, explaining its point using only facts shown on that slide. Put it in a consistent-height strip below the slide, never over the picture. Keep it readable at chat size. Burn the subtitle into every frame for that slide's full hold.

## Render and inspect

With supported tools, render one silent landscape video from slide frames above the subtitle strip, with motion between slides; do not record the screen. Hold each slide for at least one second per three newly added words, excluding text inside screenshots. Count the subtitle and changed labels as added words; the first slide adds all its words. Measure only the fully visible hold, excluding transitions. Match the rendered frames to the slide rather than using a still-frame detector that can count faint fade tails. Inspect one frame from every slide at chat size in the actual rendered file, verify readable unobscured subtitles and compare word count with the measured hold. Repair and rerender unreadable slides, then inspect again. If these checks cannot run, disclose the gap and use the failure fallback above.

Reply with ketchup's opening sentence, the actual embedded video when supported and verified, one line of work left that you can do yourself, and all waiting action items. Use the same option names in the action items as the video uses. Do not invent calls or omit a pending decision to keep the recap short. State unknown evidence as unknown.
