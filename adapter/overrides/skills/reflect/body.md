# Reflect

1. Use the active conversation or a user-supplied in-scope transcript. Do not search private application storage.
2. Examine judgment, tooling, and missed alternatives. Use real permitted reviewers if available; otherwise run a single-agent pass with those lenses and label it honestly.
3. Group findings into Accepted proposals, Rejected proposals, and Backlog. Prefer types, lints, tests, or simpler architecture over repeated prose rules.
4. Present concrete proposed edits and wait for explicit approval before changing standing skills. Approval for reflection alone is not approval to change future behavior.
5. Apply only approved edits, validate touched skills, and report results. Backlog remains local unless the user authorized filing external issues.
